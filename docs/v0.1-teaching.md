# Orvel v0.1: Teach

v0.1 is a complete, local-first teaching loop. It does not train or fine-tune a
model. Instead, it saves corrections as structured examples, retrieves relevant
examples for a later question, and supplies them as explicit context to the
model provider.

## Implemented

- Agent creation with a provider-neutral `{ provider, model, settings? }` model
  configuration.
- Local persistence of agents, conversations, messages, teachings, eval cases,
  and eval runs in an atomically written JSON file.
- OpenAI, Ollama, and Groq adapters, all implementing the same
  provider-neutral runtime contract.
- Chat histories, with assistant messages recording the teaching IDs that
  influenced the run.
- Structured teachings with original input, original response, correction, and
  optional explanation.
- Deterministic keyword-overlap retrieval plus opt-in local hybrid semantic
  retrieval, both scoped to an agent.
- Inspectable, creator-supplied teaching context injected only when matches are
  found.
- A contains-text eval with explicit limits and stored results.
- Studio routes for Agents, Chat, Teachings, and Evals.

## Teaching retrieval

The v0.1 retriever lowercases text, extracts word tokens, performs a small
singularization step (`refunds` → `refund`), removes common question words, and
scores examples by token overlap with the new user question. Only examples above
the configured score threshold are selected, with at most three injected.

For example, a stored correction about “refunds” is selected for “When should I
expect my refund?” but not “What color is the sky?”. This is deterministic,
inspectable, and deliberately replaceable by future semantic or vector retrieval
adapters. When an explicit local Ollama embedding model is configured, hybrid
retrieval can also match paraphrases using cosine similarity while keeping
lexical scoring as fallback. See
[semantic teaching retrieval](semantic-teaching-retrieval.md) for scoring,
privacy, persistence, and threshold details.

## General Knowledge

General Knowledge is optional plain text stored with an agent. It is for facts
the creator wants the agent to know from the start, such as delivery coverage,
return windows, or product details. It is not a teaching example and it does
not change how the agent should behave.

The three v0.1 context sources are kept separate:

- **Instructions** tell the agent how to behave.
- **General Knowledge** provides creator-supplied facts.
- **Teachings** are creator corrections and examples saved while using the
  agent.

At run time, Orvel sends instructions first, then General Knowledge, then only
relevant Teachings, followed by the conversation. General Knowledge is
explicitly labelled as creator-provided factual context, separate from customer
messages. v0.1 injects the entire text; document upload, chunking, RAG,
embeddings, vector search, crawling, and external sources are future work.

## Model context

Each selected teaching is rendered as a labelled creator correction containing:

- The original user question
- The earlier assistant response
- The creator-corrected response
- An optional explanation

The runtime preserves that context separately in the `ModelRequest` and also
adds it to the final model-message sequence. Provider adapters receive both the
full message sequence and the inspectable context metadata.

## Persistence

`@orvel/local` is a file-backed adapter. By default Studio writes to
`apps/studio/.orvel/data.json`; set `ORVEL_DATA_PATH` to choose a different file.
Writes are serialized and use a temporary file followed by rename. This keeps
v0.1 portable with no database service or native dependency.

It is intended for local, single-user development. Concurrent writers,
multi-process coordination, schema migrations, encryption, backup policy, and
production storage are future work.

## Provider setup

Copy `.env.example` to `apps/studio/.env.local`. For OpenAI-backed agents, set:

```bash
OPENAI_API_KEY=your_key_here
```

The key is read only in server-side Studio modules. If it is missing, OpenAI
chat and eval actions show a setup message instead of attempting a request.

### Local models with Ollama

Ollama needs no API key. Install and start Ollama, pull a model that suits your
machine, then start Studio:

```bash
ollama pull llama3.2:3b
pnpm dev
```

In Studio, choose **Ollama (Local)** and select an installed model or enter its
name. Studio queries Ollama's local model list when it is reachable and shows a
clear setup message when it is not. The default local endpoint is
`http://localhost:11434`; configure `OLLAMA_BASE_URL` only to use another
endpoint.

Create an Ollama-backed agent, chat, use **Teach** to save a correction, then
start a fresh conversation and ask a related question. The same deterministic
retriever supplies matching corrections to Ollama. An unrelated prompt such as
“What color is the sky?” does not receive a refund teaching.

Ollama runs the underlying language model locally. Orvel provides the agent
runtime, teaching, memory/knowledge architecture, evaluation, and surrounding
agent behavior. v0.1 teaching is contextual: it does not modify or fine-tune
the local model's weights.

### Hosted Groq models

For a Groq-backed agent, add this server-side setting to
`apps/studio/.env.local`:

```bash
GROQ_API_KEY=your_key_here
```

Then choose **Groq (Cloud)** in Studio. The model field remains configurable;
`openai/gpt-oss-20b` is the current default based on Groq's published active
model list. Groq controls model availability and any free-tier limits, so they
may change. `GROQ_API_KEY` is independent of `OPENAI_API_KEY`.

Groq is the inference provider. Orvel continues to provide the agent runtime,
teaching retrieval, local persistence, evals, and surrounding agent behavior.
Teachings remain contextual examples and never modify Groq model weights.

## SDK usage

The SDK has no dependency on Next.js. Compose it with a store and a runtime:

```ts
const client = createOrvelClient({ store, runtime })
const agent = await client.createAgent({
  name: 'SupportBot',
  instructions: 'You are a customer support agent.',
  model: { provider: 'openai', model: 'gpt-4.1-mini' },
})
const conversation = await client.createConversation(agent.id)
await client.sendMessage({
  conversationId: conversation.id,
  content: 'How long do refunds take?',
})
```

Use `saveTeaching`, `listTeachings`, `createEval`, and `runEval` to work with the
remaining v0.1 capabilities programmatically.

## Explicit limitations

- Teachings are contextual examples, not model-weight updates.
- Semantic retrieval is opt-in and depends on a locally installed Ollama
  embedding model; without it, lexical fallback can miss a paraphrase.
- The included eval checks whether output contains expected text. It does not
  assess broad factuality, style, or policy compliance.
- v0.1 includes OpenAI, Ollama, and Groq adapters. The runtime remains provider
  neutral, and future providers can implement `ModelProvider` outside it.

## Planned later

Database adapters, streaming, tool use, model
fine-tuning, preference learning, richer evaluators, agent versions, deployment,
and multi-agent workflows are intentionally out of scope for v0.1.
